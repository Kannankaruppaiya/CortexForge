# Competitive Landscape & Novelty Analysis

## Overview
To maintain research integrity, CortexForge distinguishes existing industry/academic capabilities from its own novel contributions.

| Capability Area | Existing Industry / OSS Approaches | Core Limitations | CortexForge Novel Layer | Verification Benchmark |
|---|---|---|---|---|
| **Code Understanding** | Naive Vector RAG (e.g., LlamaIndex, LangChain, Cursor Codebase Indexing) | Splices code into arbitrary text chunks; loses scope, call chains, inheritance, and import boundaries; no notion of validity over time. | **Deterministic Code Graph + AST Symbol Model (Tree-sitter)** with hybrid graph-traversal relational querying. | Precision of symbol dependency resolution vs AST ground truth. |
| **Agent Memory** | Chat History / Summarization (MemGPT / Letta, LangMem, Zep) | Focuses on conversational personal assistant dialogs ("User likes coffee"); mixes chat noise with architectural invariants; lacks code grounding and git commit provenance. | **Layered Project Cognitive Model (L0–L6)**: Explicit separation of Working, Structural, Decision, Failure, and Invariant memory with AST-line provenance. | Token reduction on coding benchmark tasks without lost context. |
| **Code Evolution** | Periodic re-indexing from scratch | Re-embedding an entire 100k LoC repository on every commit is computationally prohibitive and discards accumulated agent insights. | **Semantic Change Propagation**: Git diff $\to$ affected AST entities $\to$ affected graph nodes $\to$ selective memory invalidation & verification. | Stale memory detection rate and re-index CPU/time reduction. |
| **Memory Truth Maintenance** | Immutable vector stores | Once an embedding is written, it remains forever until manually wiped or overwritten, causing agents to act on obsolete patterns. | **Active Verification Loop**: Memory states (`ACTIVE`, `STALE`, `CONFLICTED`, `DEPRECATED`); automated verification against current executable code and git history. | Reduction in hallucinated or deprecated API calls during coding tasks. |
| **Consolidation** | Simple LLM summarize-all prompt | Destroys granular line provenance; aggregates noise; collapses distinct edge-case decisions into vague generalities. | **Provenance-Preserving Hierarchical Consolidation**: Clusters episodic events into durable principles while retaining original git commit and file evidence references in an archive ledger. | Information retention score vs context compression ratio. |
| **Agent Governance** | Passive lookup (agent must remember to ask) | If an agent doesn't think to ask "Has this refactoring failed before?", it repeats the same architectural mistake. | **Pre-Action Governance Checks**: Intercepts intended file modifications and surfaces historical failure episodes and conflicting constraints proactively. | Repeated failure rate across multi-step agent coding benchmarks. |
