## 3. Root-cause themes

1. **No proposition layer.** Everything above verification (confidence, conflict, staleness,
   reconciliation) operates on whole memories. A memory containing one true and one false
   statement has no representable state. This is the single largest structural gap and blocks
   §4–§10 simultaneously.
2. **Decisions are not records.** Reconciliation outcomes exist as strings in a returned
   dataclass. Nothing is persisted, so nothing is auditable, replayable, or measurable.
3. **Authority is declared but unused.** Two competing authority tables exist; the ordinal
   hierarchy that §6 requires is enforced nowhere.
4. **Truth is asserted where it should be measured.** Benchmarks, replay and snapshots present
   fabricated or current-state data as historical or measured fact — the exact failure mode
   §46/§49/§59 warn against.
5. **Idempotency is assumed, not enforced.** Changesets, webhook deliveries and consolidation
   have no keys or unique constraints.
6. **Confidence can be manufactured.** Repeated verification of unchanged evidence raises
   confidence without new information.

## 4. Remediation order (mapped to the specification's phases)

Ordered by "unblocks the most downstream correctness", not by size:

1. Authority + epistemic-state primitives (§6, §3) — prerequisite for everything else.
2. Claim / ClaimEvidence / VerificationPolicy / VerificationRun / VerificationResult (§4, §5, §7).
3. Remove confidence inflation; persist confidence components (§8).
4. Reconciliation engine producing persisted `MemoryDecision` records (§9).
5. Safe consolidation: LLM → CANDIDATE → dedup → evidence → verify → ACTIVE (§23, §25, §26).
6. `REVIEW_REQUIRED` state + approval workflow (§7, §43).
7. Success episodes, retrieval events, audit log (§17, §27, §44).
8. Idempotency keys and unique constraints: changesets, webhook deliveries, claims, decisions (§37).
9. Persisted symbol lineage (§11).
10. Snapshot content + honest replay (§35, §36).
11. Benchmark de-fabrication (§49).
12. DB-native retrieval, config/contract indexing, merge reconciliation, property/contract tests
    (§21, §14, §20, §53, §54) — larger, sequenced after the correctness core.

### 5.2 Defects found *during* remediation, not in the original audit

Each of these was found by a test written to prove a fix, which is the argument
for writing the tests rather than trusting the change:

1. **A claim about non-existent code verified as true.** Evidence anchored past
   the end of a file hashed the empty string, whose sha256 is a fixed constant;
   the same constant was computed at verification time, so the anchor "matched".
   An unresolvable anchor is now recorded as unresolved and verified as MISSING.
2. **The migration chain could not build a database.** Caught by the first
   contract test written.
3. **The secret redactor did not cover database URLs**, which section 41 names
   explicitly. The original audit credited it with this coverage — that was wrong.
4. **`alembic/env.py` overwrote any caller-supplied database URL**, so migrations
   could only ever target whatever the environment pointed at.
5. **Migrations reconfigured the host process's logging**, silencing loggers other
   code had configured.
6. **Temporal succession compared naive and aware datetimes**, raising on SQLite.
7. **Five documented environment variables had no effect** (`CORTEX_HOST`,
   `CORTEX_PORT`, `CORTEX_TELEMETRY`, `CORTEX_LLM_MODEL`, `CORTEX_EMBEDDING_MODEL`),
   in addition to the `CORTEX_EMBEDDINGS_PROVIDER` mismatch the audit did find.
8. **The README declared MIT while the package declared Apache-2.0**, and no
   LICENSE file exists at all.
9. **The migration chain could not build the production schema.** It ran on
   SQLite and had, on the evidence, never been run against PostgreSQL: a boolean
   column defaulted with `sa.text('0')`, which SQLite accepts as an integer
   literal and PostgreSQL rejects as a type mismatch. Found by pointing the
   chain at a real PostgreSQL instance. CI now runs migrations and the vector
   tests against `pgvector/pgvector:pg16`, so this cannot recur silently.

### 5.4 What changed about how this repository is tested

The suite went from 51 tests to 95, but the count is the least interesting part.
What changed is what they assert:

* `tests/contract/` builds a database from migrations alone and diffs it against
  the ORM, and checks the project's documentation against its own code.
* `tests/property/` asserts invariants across generated inputs rather than single
  cases.
* `tests/evaluation/` attacks the system with wrong, stale, duplicated,
  hallucinated and malicious memory, and walks a claim through becoming false.
* `tests/integration/test_definition_of_done.py` runs section 59's scenario end to
  end against a real git repository.
* `tests/integration/test_postgres_vector_retrieval.py` exercises the indexed
  vector path against a real PostgreSQL instance, and skips with a stated reason
  when none is configured. A skipped test says the path is unverified here; it
  does not quietly pass.

Several previously passing tests were rewritten because they asserted the old,
weaker contract — that a candidate could jump straight to ACTIVE, that repeated
verification raised confidence, that declaring a file modified marked memories
stale, that benchmark constants were still their constants. Each rewrite is a
deliberate tightening, not a workaround.
